# 产品说明

## 产品一句话

面向个人 iPhone 和 iPad 用户，持续开发一个可通过插件扩展内容来源、舒适阅读漫画与电子书，并能跟随 Aidoku 官方更新演进的统一阅读器。

## 主要用户

- 主要用户是项目所有者本人，技术操作能力有限，更关注实际阅读体验、稳定性和清楚的安装验收步骤。
- 主要设备是 iPhone 17（iOS 26）和 iPad Air 4（较新 iPadOS，精确版本待记录）。
- 项目代码和后续 GitHub 仓库保持公开。

## 核心问题

1. 官方 Aidoku 以漫画和来源扩展为核心，个人版本还需要持续增强电子书、自动阅读和语音阅读体验。
2. 旧项目存在多 worktree、多长期分支、已撤销实验和构建限制，难以判断真实基线与验收状态。
3. 个人功能必须能持续吸收官方 Aidoku 更新，不能因为一次大改而永久停留在旧上游。
4. 云端打包和真机安装成本较高，需要用自动检查收敛问题，在关键集成节点集中验收。

## 核心使用流程

### 通过来源插件阅读漫画

- 用户添加可用的 Aidoku 来源/插件，浏览或搜索内容，加入书库并进入阅读器。
- 成功时章节稳定加载，阅读进度和书库状态能够保存。
- 来源、网络或内容错误必须可理解，不静默破坏书库或进度。

### 导入并阅读本地电子书

- 用户从本地文件入口导入受支持的 EPUB、TXT，后续包括 PDF。
- 成功时书籍进入本地书库，目录、排版和阅读位置可恢复；文字内容可使用自动阅读或语音功能。
- 编码、损坏、加密或不支持格式应明确提示，并允许返回或重新选择。

### 持续阅读与辅助功能

- 用户选择分页/滚动、文字样式、自动阅读或语音阅读，并可能在前后台间切换。
- 可见页面、正在朗读的内容和保存进度应保持一致，停止辅助功能后可正常手动阅读。
- 功能中断不得造成跳章、进度损坏或无法恢复的导航锁定。

## 产品原则

- 稳定和可恢复优先于同时加入大量功能。
- 先确认现有能力和真实缺口，再决定是否增加架构或依赖。
- 插件扩展、漫画阅读和电子书阅读是同一产品的三项核心能力，但可以共享底层服务而保持适合各自内容的界面。
- 自动检查尽量覆盖回归；云端打包和真机验收集中在少量高价值节点。
- 官方上游兼容性是持续要求，每次同步都需要说明逻辑、冲突和用户影响。
- 用户数据不得被静默覆盖，阅读进度和书库变化需要可恢复。

## 当前明确不做

- 本地基线阶段不开发 PDF、批注、同步或新的在线协议。
- 不恢复已经撤销的独立 Readium 书库实验，除非重新确认产品收益和验收范围。
- 不把账号、Cookie、签名材料或私有来源凭据放进公开仓库。
- 不把构建成功当作真机功能通过。

## 重要限制

- 许可证：上游采用 GPL-3.0，公开修改版需保留许可证并提供相应源码。
- 开发平台：当前主要开发环境是 Windows，无法本地运行 Xcode 和 iOS Simulator；编译依赖 macOS/GitHub Actions。
- 安装：无签名 IPA 仍需用户通过侧载工具签名安装。
- 费用：新增付费服务、私有 Actions 用量或商业 SDK 前必须单独确认；当前项目保持公开。
- 语言：优先保证英文、简体中文和繁体中文已有界面不退化。

## 尚未决定的产品问题

- EPUB、TXT、PDF 最终采用独立电子书入口，还是继续从现有本地文件入口进入；开始 PDF/书库改造前确认。
- 插件管理在个人版本中需要增强到什么程度；默认继续兼容 Aidoku 现有来源机制，不先建立新的插件协议。
- iPad Air 4 的准确 iPadOS 版本；首次真机验收时记录。

## 个人版本需求台账

已经确认并需要跨上游同步长期保留的具体行为，统一记录在 `docs/PERSONAL_REQUIREMENTS.md`。上游同步、回归审查和集中真机验收均以其中的稳定编号为准。
