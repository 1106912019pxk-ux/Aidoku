# 旧项目有效能力迁移矩阵

基线：旧最终功能点 b0baed46；旧稳定 main 为 df996442；共同祖先 45fe8231；新官方基线 ae20b10e。

本矩阵按最终用户行为判断，不按 77 个旧提交逐个搬运。状态含义：

- 保留并迁移：产品目标仍需要，新基线尚无等价完整行为。
- 先对比上游：上游已有相近能力或底层已重构，先确认缺口再写代码。
- 暂不迁移：实验、已撤销路线或缺少稳定验收。
- 流程重建：保留目标，但不继承旧实现中的临时限制。

## 迁移切片

1. 上游替代审计：设置、条漫自动滚动、文字阅读修复和来源 actor 重构。
2. 来源宿主适配：PICA/E-Hentai 相关用户体验，逐项决定宿主或插件归属。
3. 阅读核心：文字设置、自动阅读、TTS 状态机、后台媒体和可视页同步。
4. 本地电子书：TXT 解析、导入、索引、字体解析和对应测试。
5. 集成收敛：静态检查、两次以内非打包云端编译、一次最终无签名 IPA 和一次双设备集中验收。

## 减少打包和真机次数的验证策略

- 每个切片先做代码级检查和可运行的单元测试，不生成 IPA。
- 第一次云端编译放在阅读核心完成后，只处理编译、并发和工程引用问题，不交付安装。
- 第二次云端编译放在 TXT 与字体迁移完成后；若第一次已足够稳定，可与最终 archive 合并。
- 最终 IPA 覆盖全部迁移能力，集中在 iPhone 17 和 iPad Air 4 验收。
- 只有自动检查无法证明的页面、字体、后台音频、旋转/分屏和大文件行为进入真机清单。
